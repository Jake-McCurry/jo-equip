
"# SEO Task: SEO-001
## Task Name: Website-Wide URL Canonicalization & URL Consistency Audit

You are acting as a Senior Technical SEO Engineer and Full-Stack Web Developer.

Before making any changes, thoroughly analyze the website's routing architecture, URL generation logic, metadata implementation, XML sitemap generation, internal linking, structured data implementation, deployment configuration, and overall URL handling.

Do not assume the website should use trailing slashes or non-trailing slashes. First determine how the application is designed to serve URLs and identify the preferred URL format based on the existing routing behavior.

---

## Objective

Perform a comprehensive website-wide URL consistency audit and ensure that every indexable page uses a self-referencing canonical URL that exactly matches the final accessible URL served by the application.

The implementation should establish a single, consistent URL format across all SEO signals without making assumptions about trailing slash preferences.

The canonical URL should always match the final preferred URL that users and search engines access.

---

## Current Observation

An inconsistency has been identified.

Example:

Sitemap URL:
https://equip.jesusonline.com/channels/

Canonical URL:
https://equip.jesusonline.com/channels

This may indicate an inconsistency between sitemap generation and canonical URL generation.

Before making any changes, verify which URL version is actually considered the preferred version by the application.

Do not simply remove or add trailing slashes.

Instead, identify the root cause and implement the correct long-term solution.

---

## Requirements

### 1. Analyze Website URL Behavior

Review the routing configuration and determine how URLs are handled across the application.

For every page, determine:

- Final accessible URL
- Redirect behavior (if any)
- Preferred URL version
- Canonical URL
- URL generation logic

Examples:

If

https://domain.com/page

redirects to

https://domain.com/page/

then the canonical should be

https://domain.com/page/

If

https://domain.com/page/

redirects to

https://domain.com/page

then the canonical should be

https://domain.com/page

If neither version redirects, analyze the routing configuration and determine the intended preferred version before making any changes.

---

### 2. Self-Referencing Canonical URLs

Ensure every indexable page has a self-referencing canonical URL.

The canonical URL must exactly match the final URL served to users.

Verify consistency for:

- Protocol (HTTPS)
- Hostname
- URL path
- Trailing slash behavior
- URL casing (where applicable)

Do not generate canonical URLs that differ from the actual accessible page URL.

---

### 3. XML Sitemap Consistency

Analyze how the XML sitemap is generated.

Determine whether it is:

- Framework generated
- Dynamically generated
- Build generated
- Manually maintained

Ensure that every URL included in every XML sitemap exactly matches the canonical URL for that page.

Do not manually edit generated XML files.

Instead, fix the underlying sitemap generation logic so that future sitemap updates remain consistent automatically.

Review all sitemap files, not only sitemap-0.xml.

---

### 4. Website-Wide URL Consistency

Review every SEO-related URL reference throughout the website, including:

- Canonical URLs
- XML Sitemap
- Internal navigation
- Breadcrumb links
- Open Graph URLs
- Twitter metadata
- JSON-LD structured data
- hreflang URLs (if implemented)
- Pagination URLs (if applicable)
- Any additional SEO-related URL references

Ensure all references use the same preferred URL version.

---

### 5. Redirect Review

If URL inconsistencies require redirects, implement permanent (301) redirects where appropriate.

Avoid redirect chains.

Ensure only one preferred version of every page exists.

---

### 6. Root Cause Analysis

Before implementing any fixes, identify the root cause of the inconsistency.

Determine whether the issue originates from:

- Metadata generation
- Routing configuration
- Sitemap generation
- URL helper functions
- Framework configuration
- Build process
- Deployment configuration
- Other application logic

Implement the fix at the source rather than applying temporary manual changes.

---

## Validation Requirements

After implementation verify that:

✓ Every page uses a self-referencing canonical URL.

✓ Every canonical URL matches the final accessible URL.

✓ Every sitemap URL matches its corresponding canonical URL.

✓ No URL inconsistencies remain.

✓ No duplicate URL variations are generated.

✓ XML sitemap remains valid.

✓ Canonical implementation follows Google's best practices.

✓ Internal links use the preferred URL format.

✓ Structured data URLs use the preferred URL format.

✓ Open Graph URLs use the preferred URL format.

✓ Redirects (if implemented) resolve correctly.

✓ Google Search Console compatibility is maintained.

✓ Cloudflare deployment remains fully compatible.

---

## Code Quality Requirements

Follow the existing project architecture and coding standards.

Do not hardcode URL changes.

Implement the solution at the source of URL generation so that all future pages automatically follow the same URL strategy.

Do not introduce unnecessary complexity.

Keep the implementation modular, scalable, and maintainable.

Do not modify unrelated functionality.

---

## Deliverables

After completing the implementation, provide:

1. A summary of the analysis performed.

2. The website's actual preferred URL behavior.

3. The root cause of the inconsistency.

4. The files modified.

5. The changes made to canonical URL generation.

6. The changes made to sitemap generation.

7. Any redirect rules that were added or modified.

8. Confirmation that every page now uses a self-referencing canonical URL matching the final accessible URL.

9. Confirmation that all sitemap URLs, canonical URLs, internal links, structured data URLs, and metadata URLs are fully consistent.

10. Any recommendations for additional URL standardization or SEO improvements discovered during the audit.

Do not make assumptions.

Analyze the current implementation first, identify the preferred URL behavior of the application, and then implement a scalable, long-term solution that ensures complete URL consistency across the entire website."
