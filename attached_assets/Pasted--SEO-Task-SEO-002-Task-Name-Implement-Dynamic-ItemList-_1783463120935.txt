
"# SEO Task: SEO-002
## Task Name: Implement Dynamic ItemList Structured Data for the Playlists Listing Page

You are acting as a Senior Technical SEO Engineer and Full-Stack Web Developer.

Before making any changes, thoroughly analyze the website architecture, routing system, structured data implementation, metadata generation, page components, and the playlist listing logic.

Do not assume the framework being used. First identify how the Playlists page is rendered and how playlist data is fetched before implementing any structured data.

---

## Target Page

https://staging-equip.jesusonline.com/playlists/
---

## Objective

Implement dynamic JSON-LD ItemList structured data for the Playlists page to help search engines understand that this page represents a collection of playlists.

The structured data should accurately represent the visible content on the page and automatically stay synchronized as playlists are added, removed, or reordered.

Do not hardcode playlist information.

The implementation should dynamically generate the schema using the same data source that powers the visible playlist listing.

---

## Requirements

### 1. Analyze Existing Structured Data

Before implementation:

- Determine whether structured data already exists on this page.
- If ItemList already exists, review and improve it if necessary.
- Avoid duplicate structured data.
- Preserve any valid existing schema.

---

### 2. Implement ItemList Schema

Implement a valid JSON-LD ItemList schema following Schema.org and Google's Structured Data recommendations.

The ItemList should represent the playlists displayed on the page.

Include:

- @context
- @type = ItemList
- name
- description (if appropriate)
- numberOfItems
- itemListOrder (when applicable)
- itemListElement

---

### 3. Generate List Items Dynamically

Each visible playlist should generate one ListItem.

Each ListItem should include:

- @type = ListItem
- position
- name (playlist title)
- url (canonical playlist URL)

The position value should reflect the actual visual order shown on the page.

The URL should always use the canonical version of the playlist URL.

Do not include non-canonical URLs.

---

### 4. Data Consistency

The structured data must exactly match the visible page content.

Do not include:

- Hidden playlists
- Draft playlists
- Deleted playlists
- Pagination placeholders
- Empty list items

The numberOfItems property must equal the total number of visible playlists.

---

### 5. Dynamic Generation

The implementation must automatically update whenever:

- New playlists are published.
- Existing playlists are removed.
- Playlist order changes.
- Playlist URLs change.
- Playlist titles change.

No manual schema updates should ever be required.

---

### 6. URL Validation

Before generating the ItemList:

Verify that every playlist URL:

- Matches the page's self-referencing canonical URL.
- Uses the preferred URL format adopted by the application.
- Returns HTTP 200.
- Does not redirect.

Only canonical URLs should appear in the structured data.

---

### 7. Code Quality

Follow the existing project architecture.

Generate the schema from the application's existing playlist data source.

Do not duplicate business logic.

Do not hardcode values.

Keep the implementation modular, reusable, scalable, and maintainable.

Do not affect page performance or existing functionality.

---
