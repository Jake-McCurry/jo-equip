  - file_title

Specifically investigate these possible causes:

1. Repeated event-listener registration

Look for event listeners created inside React effects, components, route handlers, layouts, or initialization functions that may run multiple times.

Flag patterns such as:

useEffect(() => {
  document.addEventListener("click", handler);
});

where there is:

- no dependency array
- no cleanup function
- an unstable handler reference
- repeated execution on route changes
- repeated execution during component rerenders

Also inspect whether React Strict Mode could expose duplicate initialization during development, while determining whether duplication could also occur in production.

2. Multiple tracking implementations

Determine whether the same PDF interaction is tracked by more than one mechanism, such as:

- an element onClick handler
- a document-level delegated click listener
- a window-level listener
- a reusable DownloadButton component
- a PDF-link component
- a route-level listener
- an analytics utility
- a direct gtag event
- a dataLayer.push event
- automatic link tracking code
- a server-side or API event

Flag any situation where one click could call two or more of these.

3. Event bubbling

Check whether nested elements can each trigger tracking. Examples:

- button inside an anchor
- icon inside a button
- click handler on both a child and parent
- card-level click handler plus link-level click handler
- event delegation plus component onClick

Determine whether event bubbling could cause multiple pdf_download pushes.

4. Repeated analytics initialization

Check whether:

- GTM-PKJQNCS is inserted more than once
- the GTM script is present in both the HTML template and React code
- Google Analytics is initialized directly in addition to GTM
- the same layout or provider mounts multiple times
- scripts are injected after each route change
- multiple analytics providers are active
- both production and legacy tracking code execute

5. Functions called more than once

Trace every function that can send pdf_download and identify all callers.

For each event-sending function, document:

- where it is defined
- every place it is called
- whether one interaction can reach it through multiple call paths
- whether rerendering or route changes can register additional callbacks
- whether asynchronous callbacks, promises, or retries can call it again

6. PDF-link handling

Review every place that renders or handles PDF links.

Check for:

- duplicate click handlers
- links that call tracking before navigation and again during navigation
- buttons that programmatically call link.click()
- tracking called both before and after opening the PDF
- target="_blank" logic
- download attributes
- router navigation
- programmatic window.open()

- pointer and mouse handlers both firing
